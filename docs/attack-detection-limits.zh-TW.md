# 攻擊偵測：v0.4.0 已知限制

[English](attack-detection-limits.md)

v0.4.0 內建 27 條攻擊特徵，不會為了攔下攻擊的各種改寫寫法而擴充。
以下是已知會漏掉的情況。漏掉只會影響告警：漏報，或判得比較輕。這些情況都不會讓 Shentu 封錯 IP。
v0.4.0 不會自動封鎖：`block_ip` 一定要經營運者確認。在這個版本裡，「證據要查證過」的檢查只涵蓋 SSH 登入證據；不讓未查證的網站紀錄拿來封鎖的閘門，在 P5（#91）才加上。

## 完全看不到的部分

- **只支援 Linux**：攻擊偵測只讀 Linux 主機的紀錄。
- **只讀標準格式的紀錄**：只讀 nginx 和 Apache 的標準存取紀錄格式。用了 `escape=none` 或自訂時間格式的紀錄會被拒絕。
- **看不到請求本文**：存取紀錄不記 POST 本文、JSON 或上傳檔，放在那裡的 payload 永遠看不到；這種請求打到路由時，最多只到 L1。
- **最多解碼兩輪**：網址編碼最多解兩次（含 `%u` 和過長的 UTF-8）。base64、gzip 和其他編碼都不解。
- **無法判定的請求只計數，L1 不推播**：無法判定的請求只會計數；L1 的嘗試不會推播成告警。
- **未查證的紀錄不能拿來封鎖**：Shentu 無法查證的紀錄（例如網站使用者寫得到的檔案），告警會註明，而且不能當成封鎖的依據。

## 可能漏掉的請求

- **改寫過的路徑穿越**：特徵只認最直接的寫法。攻擊者在路徑中多塞斜線或反斜線、`./` 片段或 `;` 路徑參數，就可能比不到。
- **改寫過的 SQL 注入**：以下寫法可能比不到：
  - 在關鍵字之間插入註解；
  - 用空格、Tab 以外的空白字元；
  - 用註解收在值的結尾；
  - 對數字下不帶引號的恆真條件。
- **改寫過的指令注入**：以下寫法可能比不到：
  - 用完整路徑呼叫指令；
  - 用特徵清單以外的指令；
  - 用引號把指令名稱拆開。
- **改寫或換位置的 Log4Shell 查詢**：用巢狀查詢拼出來的寫法可能比不到。放在 Referer 標頭裡的也可能比不到，因為目前不檢查這個標頭。
- **改寫過的反序列化內容**：
  - PHP 序列化物件的長度前面加了正負號，或是自訂序列化格式，都可能比不到。
  - Java 那條特徵裡，比對原始序列化位元組的分支永遠不會命中，因為比對前會把文字轉小寫；base64 和 hex 形式照樣比得到。
- **其他 PHP 串流包裝**：特徵涵蓋 `php://filter`、`php://input`、base64 的 `data:`、`expect://` 和 `zip://`。其他包裝（例如 `glob://`、`compress.zlib://`、`phar://`），以及不是 base64 的 `data:`，都比不到。
- **Flarum 開放重導向（composer-cves）沒有斜線的寫法**：重導目標只寫通訊協定加冒號、沒有 `//`，可能比不到，但瀏覽器照樣會跳到外站。
- **Flarum 掛在名稱有點的目錄下**：Flarum 登出路由有錨定，前面只能是目錄，或是緊接在路由前面的 `index.php`。Flarum 掛在名稱有點的目錄下（例如 `/v1.2/`）會漏判。
- **路由參數裡有編碼過的 `/`**：路由是用解碼後的路徑比對。路由參數的值裡有編碼過的 `/` 時（例如 `/files/:name`），請求對不上這條路由；能吃多段路徑的路由不受影響。
- **WordPress 外掛**：目前沒有針對個別 WordPress 外掛漏洞的特徵。有人攻擊主機上有漏洞的外掛時，只有被通用類別特徵抓到才看得見，而且不會對應到那個外掛的 CVE。

## 參數名稱與路徑段

類別特徵也會拿參數名稱和路徑的每一段來比對，所以一般流量裡能被比中的文字變多了。名稱或路徑段裡剛好有類別特徵的文字時，會列為雜訊；路徑段只有在路由的 placeholder 取到那一段時，才算進 L2。

## 為了不誤判一般文字而收窄的特徵

有三條類別特徵收窄過，以下一般文字不會再被比中：

- 常見英文字後面接空格和括號，例如「system (」；
- 搜尋字串裡的引號、空格、兩個減號；
- 分號後面接 id，再接其他字。

代價是會漏掉一些寫法：函式名稱和括號之間有空格的呼叫，只有參數看起來像程式碼（引號、`$` 或另一個呼叫）時才抓得到；引號後面隔了空格才開始的註解，只有收在值的結尾時才抓得到；在分隔符號後面帶參數執行的 id 抓不到。

## 實測偵測率

數字來自評估工具（`tools/detecteval`，PR #94），在 detect-eval 8f4d496 量測，用的是 detect-p5 6c54200 的特徵組。這些數字不含本分支的改動（參數名稱、路徑段、錨定路由、三條收窄的特徵）。#87、#90、#91 都併進 integ 之後會再重量。

數字的意思：

- **「偵測到」**：模板轉成的請求行裡，有任一條同類別的特徵命中。這不是告警，也不是主機上的 L2。
- **「誤報」**：一般請求裡，有任一條掃描器以外的特徵命中。
- **樣本是合成的**：由 nuclei 模板轉出的請求，加上用固定種子產生的請求，不是真實流量。

結果：

- **全部模板：偵測率 36.4%（3819 個中 1390 個）。**
  - 資料來源：nuclei-templates v10.5.2（commit 5442582a），`http/` 底下 11835 個模板。
  - 無法轉換的 1147 個、未分類的 6618 個、`rce-unspecified` 的 251 個，都不算進分母。
- **正常流量：1216 筆請求，沒有誤報。**
  - 請求來自 8 個應用（WordPress、Django、Flask、Laravel、Express、Immich、Nest、Next）的 152 條路由，每條 8 筆。
  - 樣本只有這麼多，所以只能說誤報率大約在 0.25% 以下（95% 信賴上限）。
- **主機真的有這個漏洞時：10 個模板中 3 個有告警。** 逐項如下，取自 `-explain-host`。
