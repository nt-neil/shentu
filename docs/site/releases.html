  21. v0.5.6 11-24

    127 rules

    15 changes

    • A file cut short says what cut it (#172). The code audit's unfinished files carry a cause: the token cap, the file's time limit, nesting, a rule's work cap for following calls, the project's cap (its time, memory or tokens), a call that may reach another file with no one callee to follow, or a callee's summary cut short (with why: its own work cap, a chain of summaries too long, too many parameters, or a cut inside it). The CVE bench counts files whose calls were not all followed, which it did not count before, and lists cuts by cause.
    • PHP function and method names in sinks and sanitizers match in any case, as PHP calls them (#189). System($_GET['x']), SYSTEM(...), \SYSTEM(...), System(...) inside a namespace and Shell_Exec($c) in a function a call reaches now report as the lower-case spelling does, and a sanitizer written EscapeShellArg($x) cleans. A method that happens to be named system ($o->System(...), Task::SYSTEM(...)) is still no sink. JavaScript and Python names keep their case. A builtin named in a string with an escaped backslash (array_map('\\system', $x), "\\system"), which PHP reads as \system, is that builtin as well. A pattern naming a PHP function no longer matches a class built with new (new File($p), new System(...)) or a function of a namespace (Storage\file($p), and namespace\file($p) in a file that declares a namespace), as the lower-case new file( and A\file( did before; \file($p) is still PHP's. The method and class names of member patterns match in any case too (#198): $wpdb->Query(...) and $wpdb->GET_RESULTS(...) are php-sqli-wpdb-unprepared's sinks, $wpdb->Prepare(...) cleans, and DB::RAW(...) is a sink; a variable keeps its case ($WPDB is not $wpdb).
    • Calls through callables are followed (#182, #184, #188). A PHP function that calls its own parameter ($cb($v), as tap() and Arr::first() do) is followed at each caller with what the caller passes: a closure, a function name ('run_cmd', 'Cmd::run'), an array callable ([Cmd::class, 'run'], [$this, 'run']) or a first-class callable (run_cmd(...)). A closure handed to a PHP builtin that calls it (array_map, array_filter, array_walk, usort, array_reduce, preg_replace_callback, call_user_func and others) is analysed with the input the builtin gives it, and a builtin's name given as the callable is that builtin: array_map('system', $_GET['x']) and array_map(function ($v) { system($v); }, $_GET['a']) now report. Fewer files are left with calls not followed (#174, #178, #179, #182): Python's standard-library imports (import json in a package with its own json.py) and a closure that cannot leave its function are no longer taken as calls of the project's other files. On the E7 corpus, laravel-framework's unfinished files went from 280 to 115 and Django's from 135 to 24.
  22. v0.5.7 11-26

    127 rules

    20 changes

    • PHP rules read filter_input(). A value from filter_input(INPUT_GET, ...), INPUT_POST or INPUT_COOKIE, and from an application's own method of that name (->filterInput(, ->filter_input() when its first argument is one of these constants, is request input in each PHP rule that reads $_GET, $_POST or $_COOKIE. A first argument that is a variable or another constant (such as INPUT_SERVER) is not. A number or bool filter (FILTER_VALIDATE_INT, FILTER_VALIDATE_BOOL, FILTER_SANITIZE_NUMBER_INT and others, also as a named filter: argument) gives a value with no input in it, but not with flags or-ed into it (FILTER_VALIDATE_INT | FILTER_NULL_ON_FAILURE is another filter ID, which PHP 7 reads as FILTER_DEFAULT); FILTER_SANITIZE_SPECIAL_CHARS cleans in the rules that take htmlspecialchars() as a sanitizer; a URL filter does not clean.
    • macOS: a listening socket netstat gives with pid 0 has no owner to name, so the list of listening ports is marked partial and says how many, no longer complete as if every owner were known.
    • PHP rules know an application's own guard function. A function that returns true only after a check of its path parameter (an allowlist, as Welcart's usces_is_reserved_file(), or realpath($p) with strpos($real, $base) === 0) cleans the value it was given where its result is true (if (guard($f)) { ... }, or after if (!guard($f)) { die(); }), also as a method of another class. A guard that assigns its parameter, returns true before the check, or only checks that the file exists does not. strpos( and stripos( compared === 0 or !== 0 are a prefix check in the path rules, of their first argument only (strpos('/var/logs/', $real) holds for / and /var). Where realpath($p) found the file, $p is no longer a URL or a phar:// wrapper for the server-side request and phar rules; the path rules still report it. An in_array() lookup of basename($p) or intval($id) no longer validates $p or $id: ../../x/log.txt and 1 OR 1 pass it.

  • package_vulns on Ubuntu: a USN covers every release it fixed, and its aliases name CVEs some other release has only (USN-7980-1 names CVE-2025-11187, which OSV has for 25.10 and 26.04, not 24.04). Of a USN only the CVEs OSV also lists for that package on the host's release count now, so a CVE of another release is no longer marked actively exploited (KEV) on this host, nor counted on the surface, nor taken for a CVE OSV already reports when a third-party PHP or nginx is compared with upstream. A USN whose package has no CVE-named advisory to tell its CVEs' release by is counted in kev_unchecked and named, never dropped quietly.
  • Windows: Shentu's own files opened without following a link (the dispatch log, the AI budget reservations, the auto-incident and audit locks) are checked and used through one handle, opened not following a symlink or junction. Before, the file was looked at, then opened by its name, and the two compared in a way that cannot tell on Windows: a file swapped for a link in between was opened through the link. A deduplicated file (Windows Server Data Deduplication) is still opened; another kind of reparse point is said, not opened.
  • Windows: site_profile, the processes, listening ports, accounts and SSH tools, log_search and the Python site-packages check go by the host read (Windows or not), as the macOS ones do, not by the machine running the check. Replaying a Windows host's reads, or checking one from another machine, no longer gives the Linux answer, and site-packages matches a Windows venv's RECORD paths (without case, as Windows names files, and with an old pip's \): a genuine .pth a package's RECORD lists is no longer reported as unknown. On a Windows host where Apache shows (an httpd.exe process or service, C:\Apache24\conf\httpd.conf or C:\xampp\apache), site_profile's risks list one more unchecked risk, unchecked:notyet:apache:windows: Apache there is not checked yet, so CVE-2026-119618 (HTTP/2) is not evaluated. The daily report lists it under "Not checked by this release yet", not under the missing-permission heading.
  • app_vulns and the daily patrol check the Python packages in Docker images against OSV as PyPI, with the CISA KEV mark. They are read from Docker's overlay2 image store on disk; no container is started and the daemon is not asked. Each tagged image's layers are stacked as overlayfs stacks them: a higher layer's file replaces a lower one's, a deleted file (a whiteout) removes only that name in its own folder, and an opaque folder hides the lower layers' files in it. Until now a package inside an image was not checked at all. A store that is there but could not be read (not root, a file not read, past the bounds of 50 images, 200 layers or 200,000 files) is reported as not checked, each such line of the daily report on its own; a host with no Docker store says so apart. The store's folders are not followed when they are symlinks, and when the run is stopped the images left are said not checked. Images in containerd's store (new Docker releases keep them there by default: /var/lib/containerd, or containerd-snapshotter turned on in daemon.json) are not read by this release: partial says so rather than "no images", and the daily report lists it under what this release does not check yet. The store is read only when the host read is this machine itself: a replay says the images were not checked. A .pth in an image is never taken as a tool's own.
  • package_vulns' overview tells how many of the vulnerabilities a fix is known to be out for (fix_available, also per package) and how many it is not known for (fix_unconfirmed). A fix is known when the advisory is a distribution's update notice (DSA, DLA, USN, RLSA, ALSA, SUSE-SU) or an ALAS. A php.net or nginx.org entry is counted in fix_available too: the fixed release is out upstream, though the repository the package came from (sury, for one) may not have packaged it yet. The rest, such as a CVE entry of Debian's or Ubuntu's tracker, are unconfirmed: the overview does not fetch each advisory to tell, and fix_note says that unconfirmed is not "no fix". Until now the count mixed them; package set still gives each one's fixed_version, without the counts.
  • The patrol's cooldown of sudo:nopasswd compares its rules too, every one (not only the three its text shows): when a no-password rule is added or removed while the risk is already reported, it is pushed again within the cooldown; the same rules stay quiet as before.   • A Debian or Ubuntu package held with apt-mark hold (dpkg state hi), or marked for removal but still installed (ri, pi), is checked as an installed one is. Runs lightly

  • Attack detection reads PHP's error logs and journald's messages as written, not masked first: a request's text echoed before PHP's location (an unclosed private key marker) no longer takes the location with it, so the sink keeps its error-log evidence. The events keep only times and locations, and nothing from them is output. That evidence counts only from a source the web account cannot write: a journald message from a unit's root process while the application cannot run as root. An error log file (nginx's, Apache's, PHP-FPM's) and PHP's own messages, which FPM's workers write (to a file, syslog or stdout), never count: on a PHP-FPM host a request does not reach L3 by them.

Known issues

  • A Python package's RECORD with a line that opens a quote and never closes it is read as one field from there to its end: the rows after that line are not used, and a .pth file they would prove a tool's (setuptools, virtualenv, an editable install) is listed as not proven (reported more, never hidden).
  • A command's own password is not masked when it is only JSON punctuation (, : { } [ ] and spaces), past a space in it (a command line joins argv with spaces; quoted in a shell line it is masked whole), past an unquoted ;, | or & in a log line or a shell's history, in a JSON argv printed over several lines or after a string holding ], or given to another program's option (sshpass -p, redis-cli -a, ldapsearch -w, smbclient -U user%<secret>, mongosh -p, htpasswd -b, curl's --pass and -E cert:<secret>).
  • The cloud-init sudo warning reads PasswordAuthentication only: it is raised although AuthenticationMethods publickey allows keys alone, and not raised when PasswordAuthentication is no but KbdInteractiveAuthentication yes with UsePAM yes still takes a password.
  • Drupal installed without Composer (no composer.lock) has no host check yet for core's installer advisories (SA-CORE-2026-017, SA-CORE-2026-019); one installed with Composer is reported by app_vulns through OSV, and marked as exploited when CISA's KEV catalog lists it.
  • Some checks still read texts masked when read in: on Windows event data (each field masked on its own; log_search's text of an event is masked field by field).
  • A secret whose name and value an event gives in two fields (a name in one, the value in the next) is not masked in log_search's text; Windows' own events give none so (CommandLine, ImagePath and ScriptBlockText are one field each).
  • A user's name of mysql given to an option in text (a log line, a shell's history, a cron line: --user mysql -p5432, psql -U mysql -p5432) is read as the program, and the -p after it is masked (a process's command line, judged argument by argument, is not); a file named .mysql (psql -f backup.mysql -p5432) is read so in text and in a process's command line alike.
  • log_search matches the masked text: what the mask covers cannot be found. A pattern matched against the text as written would tell, match by match, what a masked secret is.
  • A recording (a fixture) holds the masked text only, so a check replayed from it can decide otherwise than on the live host: the cryptominer check, on options the mask covered, and attack detection, which can have less error-log evidence (an error log or journald message whose location the mask covered).
  • A redirect target checked in another file (a Tornado base class's self.sanitize_next_url()) is still reported: app_code_audit reads each file on its own first, and that finding stays when the calls across files show the check.
  • js-file-upload-client-name-write reads no allowlist as a check: an upload written under the client's name after its extension or MIME type was checked against a list (express-cart 1.1.7) is still reported.
  • Input handed to a route generator that builds a path on the site is still reported in a redirect (PSR-7's urlFor(), Flarum's $url->to(...)->route(), Tornado's reverse_url()).
  • fgetcsv(): a row assigned in a while condition (while (($row = fgetcsv($h)) !== false)) is not followed into the loop, so that usual way of reading a CSV file is missed. A CSV file the application ships itself is reported as well.
  • A value escaped with a database library's ->escape() and written inside quotes is still reported (php-sqli-string-concat): the rule does not read ->escape( as a check, as some libraries' escape adds no quotes and a numeric position is left open. A Symfony body now reaches it too.
  • A Symfony body decoded with json_decode() and passed to another function loses its input there, so a field decoded in a controller and written into SQL in another class is missed.
  • After extract() of input, a property of a variable it set ($cfg->path) reads as no input: extract() of request data sets strings and arrays. extract((array) json_decode($in)) and extract(get_object_vars(json_decode($in))) can set objects whose properties are input, and these are missed.
  • A reference rule misreads a few forms. A command written out in full is still reported when it is split into adjacent string literals (os.system('ls ' '-l'), which Python joins into one) or joined from a list of literals (' '.join(['ls', '-l'])). An attribute receiver (h.env.from_string(s)) is known by its name only, even where the file assigns it (h.env = Engine()). o.system(cmd) after import os as o, and a function imported under another name (m(x) after from hashlib import md5 as m), are not reported.
  • On a non-Windows machine replaying a Windows host's recording, the code audit's ASP check, its web-root ACL check and its case-insensitive path comparison are not turned on yet, and app_vulns' and app_code_audit's path argument is refused unless it is one of the app paths exactly (v0.5.9).
  • A route model reads a handler only in the file that registers it: an elementor/editor/after_save callback written in another file than its add_action() (the hook in the main plugin file, the function in an include) is not read as one, so a fetch there is not reported. The other route models share the limit.
