v0.2.5即將發布

看得更遠

  • app_code_audit 會跨檔追蹤呼叫：在一個檔案讀進來、在另一個檔案的危險呼叫用掉的輸入，會在危險呼叫處報出，並標明來源檔案。
  • 框架路由模型：WordPress 的 hook、shortcode 與 REST 路由，Laravel 路由、Django URL、Flask 與 FastAPI 的 view，以及 Express handler 的參數都視為輸入，路由註冊在別的檔案也一樣。
  • 新的規則類別：LDAP 注入、NoSQL 運算子注入、危險的檔案上傳、弱加密與寫死的憑證；TypeScript 檔案用 JavaScript 規則檢查。
  • 稽核結果會在多次執行之間保留，大型應用程式分幾次巡邏就能掃完，不必一次跑完。

看得更準

  • 誤報更少：wp_send_json 的輸出、JSON_HEX_TAG 的資料區塊、不是 collection 的物件上的 MongoDB 查詢，以及 Django 的 _meta.get_field 檢查。
  • 已知問題：分成多次執行的稽核，仍可能有少數結果和不限時間的單次執行不同；修正進行中。

不拖慢網站

  • 稽核依伺服器調整自己：記憶體上限取 min(1 GiB、可用記憶體的 25%、服務 cgroup 的 50%)，並行數依 CPU 數與系統負載決定。
